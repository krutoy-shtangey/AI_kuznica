# Reglament AI

Reglament AI — веб-приложение для поиска ответов по внутренним регламентам. Сотрудник задаёт вопрос обычным языком и получает ответ с проверяемыми цитатами либо уточняющий вопрос. Если сведений недостаточно или применимые источники противоречат друг другу, сотрудник может создать обращение в службу качества.

## Возможности

- Локальная обработка DOCX и гибридный поиск BM25 + multilingual-e5-small + RRF с учётом подразделения и этапа.
- Ответы через Qwen3-30B-A3B-Instruct-2507 с указанием документа, пункта и дословной цитаты. Сервер проверяет источник, область применения и совпадение цитаты с индексом.
- Чат с автоматическим контекстом, история диалогов, каталог источников и аналитика использования модели.
- Служба качества с отдельной авторизацией, черновиком, утверждением, поисковой индексацией и отзывом разъяснений. Уведомление по SMTP настраивается отдельно.
- Раздельные режимы `demo-offline` для синтетических данных, `retrieval-offline` для настоящего поиска с тестовой моделью и `retrieval-proxyapi` для настоящего поиска и генерации.

## Архитектура

Браузерный интерфейс **React, TypeScript и Vite** обращается к **FastAPI** по тому же адресу. Сервер ищет по локальному индексу, рассчитанному через **PyTorch CPU**, и в рабочем режиме передаёт отобранные фрагменты в **Qwen через ProxyAPI**. Диалоги, метрики, обращения и очередь публикаций хранятся в **SQLite**. Поисковый индекс экспертов обновляется при утверждении и отзыве. В Windows процессом Uvicorn управляет локальный supervisor. Внешняя модель доступна только при явном разрешении на точное сочетание endpoint и модели.

## Запуск

Для Windows 10 см. [установку, рабочий запуск и обслуживание](deploy/windows/README.md). При готовой сборке и локальном индексе команда из корня проекта:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\deploy\windows\app.ps1 Start -Mode retrieval-proxyapi
```

Рабочий адрес — [127.0.0.1:8002](http://127.0.0.1:8002). Разрешение на ProxyAPI, ключ и параметры SMTP задаются в локальном `.env` по образцу `.env.example`. Рабочий корпус, SQLite, индекс и секреты готовятся локально. Для внешнего показа предусмотрено отдельное включение и закрытие доступа по умолчанию.

## Клиент модели

Клиент `backend.llm` проверен с Python 3.12. Целевая совместимость исходников — Python 3.11. Для локального запуска установите `requirements.txt` в окружение проекта и заполните локальный `.env` по примеру `.env.example`. Приоритет имеют переменные окружения. Существующий `.env` можно дополнить нужными параметрами.

```sh
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m unittest discover -s tests -v
```

`LLMClient.complete_text(system, user)` возвращает текст. `complete_json(system, user, schema)` принимает объектную модель Pydantic и проверяет JSON локально. Для типов агента используйте `AgentDraft`. Идентификаторы диалога и обращения передаёт приложение при преобразовании черновика в `AgentResult`. Приложение также проверяет применимость источников и допустимость полей для каждого сценария.

По умолчанию используется проверенный с текущим endpoint режим `json_object`. Режим `auto` начинает со строгой схемы и при явном отказе провайдера последовательно пробует `json_object` и JSON по инструкции в сообщении. Клиент запоминает пониженный режим. Отказ в формате, повторы временных ошибок и обычный запрос делят один лимит до трёх попыток. Для одиночной проверки передайте `max_attempts=1`. SDK не выполняет собственных повторов.

Каждая попытка возвращает время, режим, модель, доступные поля потребления и раздельные оценки в валютах тарифов. `LLMError` также содержит метрики выполненных попыток. Ставки ProxyAPI применяются к фактическим токенам `usage`, а тариф Alibaba Cloud даёт сравнительную оценку для выбранного региона. Без ставок или входных и выходных токенов стоимость неизвестна. Оценки не сверяются с балансом и не включают отдельные тарифы на кеш, рассуждения и другие услуги. Клиент не записывает ключ, сообщения и ответы в технические логи.

Официальные источники тарифов для примера конфигурации на 26 ноября 2026 года — [каталог ProxyAPI](https://www.proxyapi.ru/models/qwen) и [Alibaba Cloud Model Studio, Singapore International](https://help.aliyun.com/en/model-studio/model-pricing). Веса модели выпущены под Apache 2.0. Для 30,5 млрд параметров Q4 означает около 15,3 ГБ на сами веса до накладных расходов. Локальный запуск и пиковое потребление VRAM не измерялись. [Карточка модели Qwen](https://huggingface.co/Qwen/Qwen3-30B-A3B-Instruct-2507)

## Локальный API агента

Установите зависимости в существующее окружение, затем запустите сервер с синтетическим поиском. Настройки модели читаются из локального `.env`. Режим демонстрации обращается к этой модели и расходует её лимиты.

```sh
.venv/bin/python -m pip install -r requirements.txt
AGENT_DEMO_MODE=1 .venv/bin/python -m uvicorn backend.main:app --host 127.0.0.1 --port 8000 --no-access-log
.venv/bin/python -m unittest discover -s tests -v
```

В Swagger UI на `http://127.0.0.1:8000/docs` создайте диалог через `POST /dialogues`. В **Authorize** введите полученный `access_token` и используйте `dialogue_id` для отправки сообщений. Держите токен в секрете. По умолчанию режим демонстрации выключен, а неподключённый поиск возвращает `503 retrieval_not_configured`. Данные хранятся в `storage/`, который Git игнорирует.

[Маршруты, ограничения и подключение поиска](docs/integration.md#api-агента)

## Обращения и служба качества

Укажите в локальном `.env` случайный `QUALITY_ADMIN_SECRET` из 32 или более символов и при необходимости `QUALITY_ADMIN_NAME`. Перезапустите сервер. В Swagger схема `QualityBearer` принимает административный секрет, а обычная схема Bearer — токен диалога. Без административного секрета операции службы качества недоступны.

Для тестового почтового ящика укажите `SMTP_HOST`, `SMTP_PORT`, `SMTP_FROM`, `QUALITY_EMAIL` и при необходимости `SMTP_USERNAME` с `SMTP_PASSWORD`. Для STARTTLS используйте `SMTP_USE_TLS=1` и `SMTP_USE_SSL=0`, для SSL — обратные значения. Включайте `SMTP_ENABLED=1` только после проверки настроек и разрешения на отправку. `PUBLIC_APP_URL` задаёт публичный адрес для ссылки в письме. Без SMTP обращения сохраняются со статусом неотправленного уведомления.

[API, публикация, повторы и поля обращений](docs/integration.md#регистрация-и-api-службы-качества)

## Веб-приложение

Требуются Python 3.11 или 3.12 и Node.js 22.12+ (либо поддерживаемая Vite ветка 20.19+). Из корня репозитория установите зависимости:

```sh
.venv/bin/python -m pip install -r requirements.txt
npm --prefix frontend ci
```

Запускайте сервисы в отдельных терминалах из корня репозитория:

```sh
SMTP_ENABLED=0 AGENT_DEMO_MODE=1 .venv/bin/python -m uvicorn backend.main:app --host 127.0.0.1 --port 8000 --no-access-log
npm --prefix frontend run dev
```

Откройте [http://127.0.0.1:5173](http://127.0.0.1:5173). Vite направляет относительные запросы `/api/*` в FastAPI. Другой локальный адрес backend можно передать процессу Vite через `API_PROXY_TARGET`.

`AGENT_DEMO_MODE=1` подключает синтетические регламенты. При штатном запуске модель из `.env` может расходовать платный лимит. В браузерных тестах FastAPI, SQLite и синтетический поиск настоящие, модель и SMTP заменены заглушками. Реальные документы в этом режиме не используйте. Без флага и без адаптера интерфейс покажет, что поиск не подключён.

Для входа в раздел **Служба качества** задайте `QUALITY_ADMIN_SECRET` в серверном `.env`, перезапустите backend и введите секрет в форму. Секрет хранится в памяти страницы и исчезает при выходе или обновлении. Список диалогов и их индивидуальные токены хранятся в браузере на этом устройстве. Чужой токен не даёт доступ к диалогу. База знаний показывает источники из доступной истории. Аналитика ограничена выбранным диалогом.

### Production-сборка и тесты

```sh
npm --prefix frontend run build
AGENT_SERVE_FRONTEND=1 .venv/bin/python -m uvicorn backend.main:app --host 127.0.0.1 --port 8000 --no-access-log
```

Файлы из `frontend/dist` и API доступны на одном адресе [http://127.0.0.1:8000](http://127.0.0.1:8000). Для локального просмотра сборки с синтетическим поиском добавьте `AGENT_DEMO_MODE=1`; для рабочего стенда передайте реальный адаптер в `create_app(retrieval_factory=..., frontend_dir=...)`. Серверу понадобятся HTTPS, постоянное хранилище SQLite и индекса, локальная модель или отдельно разрешённый адрес модели, административный секрет и настроенный SMTP при необходимости.

```sh
.venv/bin/python -m unittest discover -s tests -v
npm --prefix frontend exec playwright install chromium
npm --prefix frontend test
```

Первый запуск браузерных тестов требует предварительной production-сборки. При наличии установленного Google Chrome можно использовать `UI_TEST_CHROME=1 npm --prefix frontend test`.
