## 8. Команды

Из корня проекта после установки постоянных Python 3.12 и Node.js с npm в обычном PowerShell:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\deploy\windows\setup.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\deploy\windows\app.ps1 Start
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\deploy\windows\app.ps1 Status
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\deploy\windows\app.ps1 Stop
```

Если Python Launcher отсутствует, setup.ps1 принимает -Python с полным путём к Python 3.12. Для краткой проверки можно указать уже созданный `.\.venv\Scripts\python.exe`; это окружение зависит от Python в кеше Codex, поэтому для постоянного сервера лучше установить самостоятельный Python.

## 9. Препятствия перед публичным запуском

1. Установить backend-зависимости и npm через разрешённое окружение с доступом к пакетам; собрать frontend.
2. Запустить локальный сервер и закончить backend/браузерные проверки, перезапуск, восстановление после падения и измерение RAM/диска.
3. Отдельно согласовать и интегрировать версию поиска Даши, поставить CPU-зависимости и E5, проверить реестр, индекс и экспертные публикации. До этого доступно только честно обозначенное offline-демо.
4. Для настоящего корпоративного поиска с ProxyAPI согласовать конкретные передаваемые данные и ограниченную конфигурацию разрешённого endpoint. Сейчас запрет внешнего API для корпоративного поиска сохранён.
5. Проверить лимит расходов в ProxyAPI и административный секрет, настроить ngrok и согласовать передачу через него. Убедиться в безопасных резервных копиях. Системные задания, сон и прочие настройки менять только по решению владельца.
