# Финальная приёмка Reglament AI

Проверка выполнена 27.11.2026 на Windows 10. В рабочем индексе 4 регламента и 737 чанков. Внешняя модель — Qwen3-30B-A3B-Instruct-2507 через разрешённый ProxyAPI.

## Что проверено

| Проверка | Результат |
| --- | --- |
| Служба качества | На копии SQLite и поколения индекса исходный вопрос вернул NO_ANSWER. Обращение создалось один раз. Доступ без административного токена отклонён. Демонстрационное разъяснение сохранено, утверждено и найдено индексом. |
| Настоящая модель | После повторного запуска приложения Qwen вернула ANSWER в новом диалоге с подтверждённым экспертным источником. После отзыва поиск исключил источник, прежний ответ помечен как изменившийся, новый диалог вернул NO_ANSWER. Израсходован один реальный вызов. Для обоих NO_ANSWER локальный поиск не вернул подходящих сведений, API не вызывался. |
| SMTP | Яндекс принял одно синтетическое сообщение через SMTP 465 с проверкой TLS-сертификата и авторизацией. Обращение и состояние sent/1 сохранены. Повтор обращения вернул ту же запись, повторная обработка очереди не отправила письмо. |
| Backend и retrieval | 129 автоматических тестов, включая локальную E5, оценку retrieval, проверку административного доступа, изоляции диалогов, лимитов и локальную эмуляцию ngrok. |
| Фронтенд | Существующая production-сборка отвечает по HTTP. Новый запуск Vite и Playwright в Codex завершился с Windows spawn EPERM. Для повторения в обычном PowerShell см. инструкцию Windows. |
| Восстановление процесса | Supervisor запустил новый дочерний процесс после намеренного сбоя старта в деморежиме. Рабочий режим перезапущен отдельно, каталог снова содержит четыре документа, обе SQLite прошли quick_check. |
| Резервная копия | SQL-состояние и фактическая копия индекса восстановлены из тестового архива в отдельный каталог. Проверены обе SQLite, 4 документа и 737 чанков. |

Проверки рабочей Qwen до этой приёмки подтвердили ответ по условиям досрочного начала работ в Технической дирекции с источниками 8.4 и 17.2, а также уточнение подразделения для вопроса о назначении руководителя проекта. Негативные результаты сохраняются. В проверке ДБРЦТ выдача контекста пропустила пункт 8.4. В проверке Дирекции ИБ модель сослалась на 2.6 и 4.2.3, которые не подтверждают требуемое назначение так непосредственно, как 2.1. Эти случаи не включены в сценарий надёжного показа. Доля правильных ответов и экономия рабочего времени не измерялись.

## Демонстрационное видео, 3 минуты

| Время | Действие |
| --- | --- |
| 0:00–0:15 | Показать рабочий режим и кратко обозначить задачу поиска по регламентам. База для записи подготовлена отдельно, SMTP выключен. |
| 0:15–1:05 | В новом диалоге спросить об условиях начала реализации проекта до подписания договора в Технической дирекции. Показать общий вывод, источники 8.4 и 17.2 и привязку к цитатам. |
| 1:05–1:40 | В новом диалоге спросить «Кто назначает руководителя проекта?». Показать уточнение подразделения, выбрать Техническую дирекцию. Показать ответ со ссылкой на проверенный пункт 4.1 или 9.3. |
| 1:40–2:50 | Спросить о жетоне вымышленного предмета. Из NO_ANSWER создать обращение, в локальной панели сохранить разъяснение с пометкой «Демонстрационное» и утвердить. В новом диалоге показать экспертный источник, затем отозвать разъяснение и подтвердить NO_ANSWER. Задержки генерации можно сократить монтажом. |
| 2:50–3:00 | Показать «Аналитику» выбранного диалога с токенами, временем и расчётной стоимостью вызова. |

Для записи и передачи видео используйте согласованный объём материалов. Панель службы качества показывается на localhost. Секреты, содержимое рабочих баз и исходные DOCX в видео и репозиторий не входят.

## Состояние развёртывания на 28 ноября 2026 года

Backend использует постоянный Python 3.12. Планировщик запускает backend и standalone ngrok до входа пользователя. После перезагрузки владелец стенда проверил сайт и ответ ассистента с телефона через мобильную сеть. Публичный показ согласован, административные маршруты доступны только локально. Полный повторный прогон браузерных тестов в Codex ограничен ошибкой из таблицы выше.

SMTP на стенде выключен. Проверка в таблице относится к тестовой отправке во время приёмки 27 ноября. Порядок запуска, проверки и резервного копирования описан в [инструкции стенда](../deploy/windows/STAND.md).
