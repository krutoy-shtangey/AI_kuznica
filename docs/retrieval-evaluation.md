# Оценка поиска по Issue #8

## Набор и методика

Фиксированный набор состоит из 28 синтетических вопросов по 13 регламентам и трём записям службы качества. Только одна из трёх экспертных записей опубликована. Один регламент отозван. Для каждого вопроса зафиксированы текст, категория, ожидаемые ID источников, фильтры подразделения и этапа и тип ожидаемого результата. Разметка записана в [тесте](../tests/test_retrieval_evaluation.py) до запуска поиска. 10 вопросов отведены на проверку настроек, 18 — на контроль. Во всём наборе 21 вопрос имеет релевантный источник и 7 ожидают пустую выдачу. Эксперимент проверяет retrieval без генерации ответа.

Сравнивались исходная версия `e33cfb3` и та же версия с изменениями BM25. Использованы локальные multilingual-e5-small и, в отдельном режиме, mmarco-mMiniLMv2-L12-H384-v1. CPU Intel Core i5-12500H, два потока PyTorch, top_k=5. После двух прогревочных запросов для каждого режима выполнено три повтора на вопрос. Качество считается один раз на вопрос, задержки — по 84 индивидуальным измерениям на режим. Холодная загрузка модели измерена один раз в отдельном процессе для каждой версии, включая инициализацию библиотек при первом вызове E5.

- Hit Rate@5 — доля вопросов с ответом, где найден хотя бы один ожидаемый источник.
- Recall@5 — средняя по вопросам доля найденных ожидаемых ID.
- MRR — средняя обратная позиция первого ожидаемого ID в пределах пяти результатов. Пропуск даёт ноль.
- FPR — доля вопросов без ответа с непустой выдачей. В таблицах «—» означает отсутствие наблюдений для соответствующей метрики.

## Исправления и настройки

BM25 распознаёт вариант аббревиатуры с точками или дефисами, только когда слитная форма уже известна по индексируемому корпусу. Для вопроса с вводной фразой BM25 сначала пытается найти источники по исходному запросу. Если выдача пуста, он повторяет поиск без ограниченного списка вводных выражений. Подход с безусловным удалением этих выражений ухудшил один результат Hybrid на локальном корпусе. Запасной режим восстановил исходную точность Hybrid в этой проверке.

На 10 калибровочных вопросах граница косинусной близости 0,80 подняла полноту Hybrid с 83,3% до 100%, а FPR с 25% до 100%. При 0,84 FPR составил 0%, полнота на калибровке осталась 83,3%. Порог покрытия BM25 0,50 и варианты с `rrf_k=20` и удвоенным весом одного из рангов дали прежние метрики калибровки. Для рабочего режима сохранены веса 1:1, `rrf_k=60`, покрытие 0,35 и граница E5 0,82. Порог 0,84 стоит отдельно проверить на размеченном рабочем наборе, прежде чем применять к нему. Reranker дал те же метрики качества, что и Hybrid, при большем P95. Он остаётся опциональным.

### Что изменилось и что проверено

- Если обычный BM25 и поиск без вводных слов ничего не нашли, адаптер рассматривает одну замену на основе словаря доступных источников. Поддерживаются одна вставка, удаление, замена или перестановка соседних букв, а также приводимые к словарю смешанные кириллическо-латинские написания. Номера пунктов, отрицания, известные аббревиатуры и слова целиком в верхнем регистре защищены от исправления. При нескольких подходящих вариантах для слова исправление пропускается.
- Ложную выдачу на точный запрос об отозванном регламенте дал пограничный результат E5 о другом процессе. Hybrid теперь отсекает слабого кандидата по регламентам при сильном лексическом совпадении с недействующей редакцией в той же области, если действующий кандидат лишён лексической поддержки и уступает ей по близости. Общий порог E5 0,82 сохранён. Смысловые запросы могут по-прежнему проходить без совпадения слов, а опубликованные разъяснения продолжают независимо проверяться через backend.
- Через create_app с реальным адаптером проверяются точная цитата, уточнение подразделения в том же диалоге, регистрация обращения и поиск утверждённого ответа. Генеративная модель в HTTP-тестах заменена заглушкой. Отдельно проверяются сохранение альтернатив при top_k=1 в search_with_context, защита ревизий, повтор записи без пересчёта неизменённого вектора и исключение источника после отзыва и перезапуска.
- Разметка регламента и цитата передаются дословно. DOCX-фрагмент без надёжного номера может оставаться в общем индексе, однако агенту он недоступен в согласованном формате идентификатора. Для поддержки таких цитат Диме нужно согласовать отдельный стабильный идентификатор и способ отображения ссылки на структурный фрагмент.
- На независимой части остался один ложный результат на вопрос без ответа и два пропуска вопросов с ответом. Поиск предлагает источники, а итоговую достаточность и противоречия определяет агент. Цифры из прежнего автоматического прогона на четырёх локальных регламентах приведены выше. Финальный аудит эти данные заново не открывал.

Для демонстрации подходит Hybrid без reranker. Он сохраняет опубликованные разъяснения и варианты разных подразделений, использует один локальный экземпляр E5 и ограничивает контекст. На измеренном наборе Hybrid достиг Recall@5 92% на независимой части при P95 15,28 мс. Для reranker остаётся результат предыдущего сравнения. Токены E5 и символы цитат не служат оценкой фактических токенов или счета генеративной модели.

### Воспроизведение финального аудита

```powershell
$env:TEST_LOCAL_E5 = '1'
$env:TEST_LOCAL_RERANK = '1'
$env:TEST_RETRIEVAL_EVAL = '1'
$env:RETRIEVAL_AUDIT_STRICT = '1'
.\.venv\Scripts\python.exe -B -m unittest discover -s tests
```

Первичный замер выполнен на состоянии ветки до финальных правок с тем же расширенным тестом. Для сравнения только двух правил аудита используйте отдельную копию. В ней отключите вызов `BM25._repair` и условный фильтр `stale_matches`, сохранив предварительную нормализацию аббревиатур и вводных слов. Снимите `RETRIEVAL_AUDIT_STRICT` для исходного прогона. Если нужен сопоставимый замер трёх режимов на 54 вопросах, задайте `TEST_LOCAL_RERANK=0` и выберите тест `-p test_retrieval_evaluation.py -k test_fixed_queries`. Для одного калибровочного поднабора предусмотрен `RETRIEVAL_CALIBRATION_ONLY=1`.

### Локальная проверка регламентов

Подготовьте локальный JSON-массив размеченных вопросов за пределами отслеживаемых каталогов, например в `data/qa-labels.json`. Для каждой записи укажите `question` и список `expected_ids`. Пустой список означает вопрос без ответа. При необходимости задайте `department` и `stage`. Для разметки используйте проверенные вопросы сотрудников и скопированные локально идентификаторы источников. Для тестового синтетического индекса пример записи выглядит как `{"question":"Что предусмотрено в пункте 8.1?","expected_ids":["regulation:meter:8.1"]}`.

```powershell
.\.venv\Scripts\python.exe -B -m retrieval.audit_local --index .\data\index --cases .\data\qa-labels.json
```

Команда читает только указанные локальные файлы и печатает метрики, число фрагментов без номера пункта, размер индекса и время поиска. Она проверяет только регламенты в формате цитат агента. Экспертные ответы проверяйте через согласованный локальный экземпляр приложения с авторитетным хранилищем службы качества.
